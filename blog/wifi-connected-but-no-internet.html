Wi-Fi connected but no internet? What to check first

Find out why Wi-Fi connects but websites will not load. Compare devices, check network sign-in, and troubleshoot Windows, Mac, or your home router.

Connected to Wi-Fi does not always mean online

Your laptop shows a Wi-Fi connection, but websites will not load. The connection to the nearby router can be working while the router's connection to the internet, a network sign-in page, or a setting on your device still needs attention.

Quick answer

Try two unrelated websites, compare another device on the same Wi-Fi, and check for a network sign-in prompt. Those three checks help you choose between troubleshooting one device and checking the internet service.

Write down the exact message, such as “No internet, secured” or “Connect to network.” A full signal icon tells you less than a repeatable test. If pages load but slowly, start with our slow Wi-Fi checklist instead.

1. Compare one website, one device, and one network

Open two familiar websites. Then try those same pages on a second device connected to the same Wi-Fi network. On a phone, temporarily turn off mobile data for this comparison so a successful page load actually tests Wi-Fi. Turn mobile data back on afterward.

Use the result as a clue, rather than a diagnosis
What you observe What to check next
Only one website fails Check that website or try another browser.
One device fails; another works Check the affected device's connection and settings.
Several devices fail on the same Wi-Fi Check network sign-in, the router, or an internet outage.
The laptop works on a trusted hotspot Investigate the original network; the laptop can get online somewhere.

For example, if your phone and laptop both fail at home, buying a new laptop Wi-Fi adapter is an early guess. If the phone works and the laptop fails on multiple networks, that is a different support conversation. Record both results before changing anything.

2. Look for a hotel, café, or guest-network sign-in

Some networks require a web sign-in or acceptance page after you connect. Check the device's network notification or open the browser. Google explains the “Connect to network” message and captive-portal checks in Chrome.

If the portal will not appear, visiting http://example.com can trigger the network's sign-in page. Use that plain HTTP page only to prompt the portal; return to HTTPS sites for normal browsing. Confirm the network name and expected sign-in process with the venue before entering information.

A certificate warning on a banking or email page is a reason to pause. Use the venue's legitimate sign-in process or ask staff for help. Our public Wi-Fi guide covers the checks to make before using a shared connection.

3. Try the built-in checks on your computer

Windows 11: save your work and restart. Check that you joined the intended network, then open Get Help and run the Network and Internet troubleshooter. Microsoft's Wi-Fi troubleshooting guide explains the available checks. Forgetting and rejoining a home network is an option if you know its password; ask IT before removing a work or school network profile.

Mac: restart and check the date and time. For a diagnostic report, hold Option while opening the Wi-Fi menu and choose Open Wireless Diagnostics. Apple's Mac internet connection guide also covers VPN software and network troubleshooting.

If only one browser fails, compare another browser before clearing data. Keep the test small: change one thing, reload the same page, and note the result. Read cache versus cookies before deleting browser data that may sign you out.

4. Check your home router and provider

If several devices are affected, use mobile data to check your provider's outage information. Note any unusual modem or router lights and compare them with the model's manual.

For equipment you manage at home, restart it using the provider's instructions. With separate modem and router units, Microsoft's guide recommends allowing the modem to reconnect before powering the router back up. Give the equipment time to settle, then repeat your original two-website test.

A factory reset erases settings and is a different operation from a restart. Leave that step for model-specific support guidance. At work, in a hotel, or on campus, send the comparison results to the network owner instead of restarting shared equipment.

Common questions

Should I change DNS immediately?

Start with the comparisons above. A failed website does not identify the cause on its own. Share the exact browser error with support before changing DNS, VPN, proxy, or security settings, particularly on a managed device.

What should I tell my internet provider or IT team?

Include the network name, when the issue began, affected devices, two websites tested, and whether another network worked. “Two devices fail on home Wi-Fi; both work elsewhere” is a useful report. Keep the network password out of the message.

Keep the next connection check simple.

If pages load but everything buffers, use a few comparisons to separate internet speed from Wi-Fi coverage.
