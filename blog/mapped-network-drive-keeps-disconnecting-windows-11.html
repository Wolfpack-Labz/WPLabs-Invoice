Mapped Network Drive Keeps Disconnecting? Windows 11 SMB Fixes

Troubleshoot mapped drives that disappear or disconnect after login, VPN changes or sleep using UNC paths, PowerShell, SMB checks and credentials.

Start here: is the share unreachable or only the drive letter missing?

A mapped drive can display a red X after startup or disconnect when you move between office Wi-Fi, home internet, and a VPN. Sometimes Windows simply has not reconnected yet; other times the file server, sign-in credentials, or network route is unavailable.

Quick answer: Check whether the server share opens by its UNC path, test DNS and SMB connectivity, reconnect to the correct VPN, and only then remap the drive with Reconnect at sign-in selected.

This guide assumes you are authorized to access the file share. Do not weaken SMB security, enable SMB1, or turn off your firewall to get a connection working. Those changes create risks and may conflict with workplace security policies.

Step 1: Record the network path and exact error

  1. Open File Explorer → This PC and find the affected mapped drive, such as S:.
  2. Right-click the drive, choose Properties if available, and record its network location.
  3. Note the error message: The network path was not found, Access is denied, The local device name is already in use, or The specified network password is not correct are not the same problem.
  4. Confirm whether coworkers can reach the same share at the same time.

A drive letter is only a shortcut to a shared path such as \\fileserver\projects. If the path works, the main problem may be the mapping. If the path fails, investigate connectivity or access first.

Step 2: Test the share directly without remapping

Press Windows + R, enter a UNC share path provided by your organization, and press Enter:

\\fileserver\projects

If the folder opens, the server and your credentials are likely sufficient for at least that share. If it does not, record the message and proceed to network testing. Avoid trying random server names, shares, or credentials.

For a business share, also check whether your company requires a VPN. A VPN indicator alone does not prove internal routing is ready; confirm you can reach another approved internal resource.

Step 3: Separate name resolution from network reachability

Open PowerShell on your Windows PC and replace the sample server name with your organization's approved server:

Resolve-DnsName fileserver.example.com
Test-NetConnection fileserver.example.com -Port 445

Resolve-DnsName checks whether DNS returns an address. Test-NetConnection checks whether a TCP connection to the usual SMB port 445 succeeds; the relevant result is TcpTestSucceeded.

  • DNS fails: Check your approved VPN/DNS setup or ask the administrator to verify the hostname.
  • DNS works, port 445 fails: The server may be offline, the route may be unavailable, or an authorized firewall may block SMB.
  • Port 445 succeeds, share still fails: Focus next on share name, permissions, authentication, and SMB policy.

A port test cannot prove that your account can access a folder. Microsoft documents Test-NetConnection for this kind of diagnostic.

Step 4: Inspect the current SMB session and mapping

Run these read-only commands:

Get-SmbConnection
Get-SmbMapping

Get-SmbConnection shows established SMB sessions to servers; an empty result is possible if no share has been opened successfully. Get-SmbMapping lists known client mappings. Compare the remote paths with the drive you expect to use.

If one map points to an old host or share, obtain the correct path from your administrator. Don't remove a mapped drive used by scripts, backups, or other applications without checking its dependencies.

Step 5: Reconnect the mapping correctly

If the UNC path opens, but the drive letter fails after sign-in, map it again through File Explorer:

  1. In This PC, select the three-dot menu → Map network drive (or the Map network drive option provided by your Windows build).
  2. Select a free drive letter.
  3. Enter the exact approved folder path, such as \\fileserver\projects.
  4. Check Reconnect at sign-in.
  5. If authorized, choose a different set of credentials only when the file server requires it.
  6. Finish, sign out and back in, and verify the mapping.

If the letter is already reserved by a broken mapping, first document the old remote path; disconnect that specific mapping through File Explorer if your IT policy allows it. Do not run net use * /delete, which could remove unrelated work connections. Microsoft explains the built-in steps in File sharing over a network in Windows.

Step 6: Investigate recurring authentication or policy errors

If the share prompts for a password on every connection, check whether you recently changed a work password, signed into a different account, or switched VPN profiles. On a managed PC, ask IT to confirm the account's share permissions, Kerberos/domain access, and any credential policy. Avoid storing service-account passwords in scripts.

Modern Windows builds may enforce SMB signing or block guest access to older devices. Microsoft's SMB protocol and signing guidance explains compatibility implications. The proper fix is to update or configure the file server securely—not to enable obsolete SMB1 or disable required protections on your laptop.

Step 7: Confirm the fix across a reconnect

Open a test file you are authorized to access, disconnect and reconnect to the VPN if appropriate, and sign out/in. Confirm the drive letter returns and the test file remains reachable. Record whether the failure happens only on Wi-Fi changes, after sleep, or when you first sign in; those details help IT reproduce timing-related failures.

If the share remains inaccessible, provide the exact UNC path, time, error, results of the DNS/TCP tests, VPN status, and whether coworkers are affected. Do not send passwords or private file contents.

Frequently asked questions

Why does a mapped drive show a red X but open when I click it?

The saved connection may be inactive until Windows attempts to use it. That is different from a path that remains unavailable after clicking.

Does “port 445 open” mean my share permissions are fine?

No. It establishes TCP reachability, not successful SMB authentication or authorization for a folder.

Should I enable SMB1 for an old NAS?

No. SMB1 is outdated. Prefer an updated NAS firmware/server configuration that supports current SMB security standards.
